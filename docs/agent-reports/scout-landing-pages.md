## 2. Stock renderers and renderer identity

Renderers are keyed by registry id: `ported` (12, `PortedTemplateView` mounts the handoff markup) and `identity` (4 legacy node-rendered, `SectionNode`). A record maps to its renderer via `template_id` (LP) / `renderer_key` (quiz). Identity rewrite protection on ui/model, at three doors: field validators (shape) in collections; server actions (`template-actions.ts` — `saveLpTemplate:163` canonicalises `template_id`, validates `slot_overrides` against the target renderer's slots); and `src/hooks/template-guards.ts` (fe29581) covering `/cms` + REST: `guardStockLpTemplateIdentity` (a `stock_key` row's `template_id`/`stock_key` immutable, 409), `guardLpTemplateDelete`/`guardQuizTemplateDelete` (referenced rows undeletable, incl. `embedded_quiz_template_id` refs), `guardLpSlotOverrides` (copy must fit the renderer). `deleteLpTemplate` (template-actions.ts:256): referenced → refuse; stock → archive (`archived_at`+`is_enabled:false`); else hard delete. Reconcile repairs a drifted stock `template_id` back (index.ts:322-330).

"Selected ID == publicly rendered ID" is enforced by ui/model's `lp-deployment.ts` strict resolution (no fallback; `LP_TEMPLATE_REFUSED` + `return null` for an unresolvable id) and **proven** by `wt-uimodel/scripts/test-renderer-identity.mts` against a real DB: A renders A, B renders B, repoint A→B re-renders B, broken id refuses (LP+quiz), clone renders its source renderer while `requestedTemplateId` keeps the clone id, `templateFellBack` is pinned false.

## 3. Semantic quiz mounts (release)

Data structure: `LpQuizMount` (`wt-release/src/lib/lp-slots/quiz-mount.ts:314-340`) = part-stream coordinates `{startPart,startOffset,endPart,endOffset}` + `slotIds` (slots inside the card — never render), `tag`, `openTag` (verbatim, so the runtime inherits the card's box), `surface` (nearest opaque ancestor background, `var(--lp-nNNN,#hex)` form), `evidence`. Located at extraction time by `findQuizMount` (quiz-mount.ts:223): answer group (≥2 all-answer-shaped buttons) + a step-indicator or nav-button ancestor; card = outermost of those two anchors; widens sideways over contentless siblings (absorbs `insurer_vs_claimant`'s progress rail — the only absorption across the 12); never a sectioning element; **exactly one region or the extractor refuses to write the module** (`scripts/extract-lp-templates.mjs:191-215`, sets exit 1). `case_type_router`'s 8 case cards are excluded by the second-affordance rule. **All 12 templates have a mount** — verified in `wt-release/src/lib/lp-templates/generated-index.json` (12/12, each `answerButtons:4`; `authority_network` anchors on step indicator only).

Composition: `composeTemplateWithQuizMount` (`wt-release/src/lib/lp-slots/model.ts:635`) yields `before/after/reference/mountHtml/htmlWithMount/mountedSlotIds`; identity `before+reference+after === composeTemplate(...).html` is asserted per template in `scripts/test-lp-slots.mts` (+ injection defense: an override or brand value cannot forge a second `data-legalos-quiz-mount`; overrides on inside-slots are swallowed). Unaddressable/absent mount → compose whole (`after:''`) — honest degradation. Render: `PortedTemplateView` (`wt-release/src/components/builder/lp/PortedTemplate.tsx`) mounts `htmlWithMount` via one `dangerouslySetInnerHTML`, then `QuizMount` portals the real `QuizRuntime` into `[data-legalos-quiz-mount]` (`useLayoutEffect`, `createPortal`), `inline` + `surfaceColor` = mount surface resolved through the template vars (`resolve-css-color.ts`), previewMode defaults safe (`quizCtx ? quizCtx.preview !== false : true`). `render.tsx` `LivePreview` threads `quiz`/`quizCtx` through; public catch-all already passed them (base page.tsx:806+).

Missing quiz: **release refuses to serve** — `resolveLpDeploymentUncached` returns null (404) when `portedTemplate?.quizMount && !quiz && !includeUnpublished` (`wt-release/src/lib/lp-deployment.ts:+231-253`), logs "See pnpm reconcile:lp-quiz". Preflight gate `quiz-bound` fails a mount-bearing deployment naming no flow (`wt-release/src/lib/publish-lifecycle.ts:+323-352`); editor refuses go-live without a flow. `src/lib/lp-quiz-binding.ts` classifies rows (`flow | legacy-migratable | legacy-needs-decision | legacy-cross-tenant | legacy-dangling | unbound`; `LOSSY_QUIZ_DEPLOYMENT_FIELDS` blocks auto-migration that would re-route leads) and `scripts/reconcile-lp-quiz-bindings.mts` (`--apply` migrates only lossless rows; non-zero exit when a human is needed). Production finding driving all of it: 3 of 4 live LP deployments had dangling `quiz_deployment_id` pointers.

## 5. Data-shape mismatches to watch

- **ui/model has zero mount awareness.** No `quizMount`/`editableSlots`/`isInsideQuizMount` anywhere in wt-uimodel. Its `SlotEditor` uses `slotsBySection` from lp-slots/model — release redefines that to iterate `editableSlots` (mount slots excluded), so the template editor heals automatically once release's `src/lib/lp-slots/*` land (release wins those files; ui/model never touched `src/lib/lp-slots/` or `src/lib/lp-templates/`).
- **Template-level `slot_overrides` can name mount slots** (written before merge, or via ui/model-only doors). Release's `validateOverrides` refuses `override_inside_quiz_mount`; post-merge `saveLpTemplate`, `guardLpSlotOverrides`, and the preflight (merged map) all inherit the refusal. Pre-existing rows with such copy will fail publish with a named slot — correct, but expect one-time operator-visible refusals.
- **Empty-box previews.** Release's `PortedTemplateView` ALWAYS renders `htmlWithMount`; portal only fills it when `quiz` is passed. ui/model's `TemplateGallery` `LpThumb`/`PreviewModal` and any quiz-less preview render LivePreview without `quiz` → post-merge every gallery card/preview shows an empty quiz box. Fix in `PortedTemplate.tsx`: `__html: quiz ? composed.htmlWithMount : composed.html` (reference card as static preview; live pages always have a quiz because the resolver 404s otherwise). ui/model's builder + LPPreviewModal already pass `quiz` (LandingPagesApp.tsx:685,843), so real previews stay live.
- **`saveLpTemplate` bug (ui/model):** `verdict.problems.join('; ')` stringifies objects → "[object Object]" errors; map `.detail` like `guardLpSlotOverrides` does.
- **Migration timestamp collision:** release `20260813_210000_locked_documents_funnel_rels` vs ui/model `20260813_210000_template_records` share a prefix; directory sort runs `l…` before `t…`; contents are disjoint/retry-safe (both touch `payload_locked_documents_rels` with IF NOT EXISTS) — keep both, no rename needed, but verify on the server that `migrate` records both names.
- **`quiz_deployment_id` write policy conflict:** ui/model still writes it from the request in `saveDeployment`; release forbids that (root cause of the dangling-pointer defect). Release's policy must win.
- **Registry-vs-records in the builder UI:** release's LandingPagesApp imports `listQuizTemplates`/`recommendedQuizTemplateFor` from the registry — grafting that verbatim would fail ui/model's `test-template-records` catalogue scan. Use ui/model's record props (`quizTemplates`, `template.recommendedQuizTemplateId`).
- **Deployment-list badge data:** release's dangling-pointer badge needs the standalone quiz-deployment rows; ui/model's page.tsx stopped loading them. Prefer computing verdicts server-side with release's `classifyLpQuizBinding` (one judgement module) and passing them to the list.
